# Модуль вебхуків (`WebhooksModule`)

Цей документ описує архітектуру підсистеми вихідних вебхуків BugTracker.
Текст відповідає стандарту спрощеної технічної мови ASD-STE100.

---

## 1. Призначення модуля

Модуль `WebhooksModule` надсилає сповіщення про події в проєкті на зовнішні сервери.
Система підтримує події створення задач, оновлення статусу, коментування та зміни призначень.
Кожен вебхук налаштовується на рівні окремого проєкту.

---

## 2. Шаблон проєктування Strategy

Для формування корисного навантаження впроваджено поведінковий патерн Strategy.
Це усуває жорстку залежність сервісу від форматів зовнішніх систем.

### 2.1 Інтерфейс `WebhookPayloadStrategy`

Усі стратегії форматування реалізують спільний інтерфейс:

```typescript
export interface FormattedWebhookPayload {
  body: string;
  contentType: string;
  headers?: Record<string, string>;
}

export interface WebhookPayloadStrategy {
  readonly format: string;
  format(
    webhook: ProjectWebhook,
    event: IssueEventType,
    data: WebhookPayloadData,
  ): Promise<FormattedWebhookPayload> | FormattedWebhookPayload;
}
```

### 2.2 Реєстр стратегій `WebhookFormatterRegistry`

Клас `WebhookFormatterRegistry` реєструє екземпляри стратегій у пам'яті.
Сервіс знаходить потрібну стратегію за значенням поля `format` вебхука:

- `GenericWebhookStrategy`: створює стандартний JSON із цифровим HMAC-SHA256 підписом.
- `DiscordWebhookStrategy`: формує об'єкти Discord Embed із колірною індикацією подій.
- `SlackWebhookStrategy`: будує блоки розмітки Slack Block Kit для корпоративних каналів.

Якщо формат не знайдено, реєстр автоматично повертає `GenericWebhookStrategy`.

---

## 3. Дотримання принципів SOLID

Впровадження патерна Strategy забезпечує такі переваги:
1. **Принцип єдиної відповідальності (SRP)**:
   Клас `WebhooksService` виконує лише збереження та диспетчеризацію запитів.
   Логіку серіалізації повідомлень інкапсульовано в окремих класах стратегій.
2. **Принцип відкритості та закритості (OCP)**:
   Розробники додають нові формати повідомлень без редагування вихідного коду сервісу.
   Новий клас стратегії реєструється у фабричному реєстрі через впровадження залежностей.

---

## 4. Безпека та повторні спроби надсилання

- **Підпис HMAC-SHA256**: Заголовок `X-BugTracker-Signature` захищає дані від підробки.
- **Повторні спроби**: Сервіс автоматично повторює надсилання запиту при тимчасових мережевих збоях.
- **Ізоляція помилок**: Збій зовнішнього вебхука не блокує виконання основної бізнес-транзакції в системі.
